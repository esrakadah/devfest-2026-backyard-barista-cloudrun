Pattern 1 · Structured output

Ask for fields, not paragraphs

'responseMimeType': 'application/json',
'responseSchema': {
'type': 'OBJECT',
'properties': {
'ratingStars': INTEGER,
'tasteVerdict': STRING,
'customerFace': STRING,
'headline': STRING,
'customerReaction': STRING,
'cityBonusTip': INTEGER,
},
'required': [ all six ],
}

The UI binds to fields

customerFace picks the image, ratingStars fills the stars. No parsing of free text.

Rules live in the prompt

Salt in a sweet order must return 1 star and “salty_sabotage”.

Personality lives in one field

customerReaction is the only creative text: the city roast.

Source: flutter_client/lib/services/cafe_judge_service.dart. Note the split of responsibilities: the schema guarantees shape, the prompt sets the business rule, and only one field is allowed to be creative. Try it yourself in Round 2: add a seventh field, for example a recommendedPairing string, and show it in the review card.
